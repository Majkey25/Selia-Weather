# Beta.22 verification

Version code 23 adds per-widget date and clock formats and keeps hourly cloud layers with the source models selected for the total-cloud median.

- 351 Android unit tests and 25 map tests passed. Debug/release lint, debug/release APKs, signed AAB and the separate release-optimized QA build passed. A Compose configuration-read lint error found during validation was fixed before the successful build.
- Cloud regressions cover odd/even medians, different source availability, missing or invalid layers, invalid totals, whole-group fallback and provider-specific layer definitions. Current sky observations, precipitation and provider probabilities remain unchanged.
- Huawei YAL-L21, Android 10: the minified QA app cold-launched and loaded real Prague weather. Its pin-widget request opened Huawei's confirmation, but accepting it did not add a new widget on the occupied launcher page. No QA widget was present in the host inventory. The temporary QA installation was removed.
- The existing development installation and its launcher widget were upgraded in place without clearing data. The actual launcher widget displayed `8.9.2026` with `3:24 PM`, then the custom pattern `EEEE d.M.yyyy` as `Tuesday 8.9.2026` with a 24-hour clock.
- The invalid date pattern `HH:mm` displayed an error and could not be applied. Its editor draft and scroll position survived a background process kill and a confirmed cold activity recreation.
- With only the development app switched to Czech, the actual widget displayed `úterý 8.9.2026` and `3:28 PM`. The clock retained the launcher's English AM/PM while the date followed the app language. The device remained on its original system language and 24-hour clock setting.
- Final saved development-widget settings were Numeric date and System clock, verified in preferences and on the launcher as `8.9.2026` / `15:29`. The development app language was returned to System. Other widget choices and production app data were retained.
- No AndroidRuntime errors were present for the final development-app process. The global crash buffer contained an unrelated UIAutomator dumper failure, not an app crash.

The physical launcher formatting checks used the debug build; the minified build received a cold-launch/data-load check, not a hosted widget check. Manual resizing and every launcher implementation were not retested in this window. Existing layout tests passed. The phone and temporary phone screenshot were released before the next test window.

This release fixes inconsistent source grouping, not demonstrated forecast skill. It adds no requests, raw satellite assimilation or newly learned weights. The September 7 drizzle report still lacks the exact location and archived inputs needed to reproduce that event.
