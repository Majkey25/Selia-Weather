# Beta.23 verification

Version code 24 fixes three paths that discarded supplied weather evidence.

- Before the fixes, the focused CHMI/model run had five failures in 58 tests; the METAR run had one failure in nine tests. After the fixes, the full 359-test Android suite and 25 map tests passed. Debug/release lint, APK/AAB and release-optimized QA builds passed.
- Model tests cover independent weather-code coverage, missing cloud/rain totals, invalid/fractional/unsupported codes, strict majorities, ties and sparse contributors. Code evidence changes conditions only, not amounts or probabilities.
- The CHMI regression runs parsing through current-condition fusion: a fresh wet gauge with absent, rejected or invalid humidity remains usable; humidity stays unknown and does not erase the model humidity. Missing temperature/gauge still retains the older complete record and its original timestamp.
- METAR tests retain local rain alongside exact supported vicinity/recent tokens. Nonlocal-only, unknown and mixed-phase reports remain unclassified; no precipitation amount is invented. Token definitions follow the [FAA observing rules](https://www.faa.gov/documentLibrary/media/Order/JO_7900.5E_with_Change_1.pdf) and [EU METAR template](https://www.legislation.gov.uk/eur/2017/373/pdfs/eur_20170373_adopted_en.pdf).

## Huawei Android 10

The release-optimized QA variant used the existing development application ID and matching development signing key so the existing launcher widget could be tested without clearing data or changing the production installation. The APK manifest and installed package confirmed version code 24 and `debuggable=false`; it is not the Play-signed APK.

- Cold activity launch completed in 676 ms. This is one launch measurement, not a benchmark comparison. Real Prague fetch diagnostics reported success for Best Match, model data, blending, METAR and CHMI. Calibration was unavailable and was not represented as active.
- The 9 September detail showed 24 hours. At 06:00 it displayed drizzle, 0.3 mm for 05:00–06:00, a separate 25% probability, and six of nine models with nonzero totals, spanning 0–1.9 mm. These are displayed forecast values, not confirmed future observations.
- Hour expansion, vertical detail scrolling, a rightward swipe to the next day and downward handle dismissal worked.
- Observed radar loaded a 13:50 UTC frame. The model map loaded in fullscreen, reached the next day's 02:00–03:00 UTC interval and started playback. The screenshot showed a loaded forecast area rather than an empty map. This is model output, not future radar observation.
- The actual minified launcher widget retained the numeric date through the upgrade, changed to `2026-09-08` / `3:57 PM`, and returned to `8.9.2026` / system time. Other widget settings remained in place. Manual resizing was not repeated in this window.
- The archive opened with 1,820 daily records from 7 September 2021 through 31 August 2026. Selecting the latest available 30 days showed 2–31 August and a grid-estimated 91.7 mm total with 30/30-day coverage. This is NASA POWER data, not a local rain-gauge total.
- Ask AI opened its disclosure and Android's CSV share chooser. The prompt retained the full-archive scope, the shorter focus period, missing-data cautions and an English-answer instruction. ChatGPT appeared as an installed recipient. No recipient was selected; no external upload or AI answer was tested. Gemini, Claude and Grok were not present in this chooser.
- No AndroidRuntime errors were logged for the QA process. The temporary phone screenshot was removed and the phone released early at 16:00 CEST. Production data, system settings and the native viewport were unchanged.

These checks verify processing and interaction behavior. They do not demonstrate a worldwide forecast accuracy gain or reproduce the user's September 7 drizzle event without its exact location and archived inputs.
