# Beta.26 verification

Version code 27 fixes day navigation, compact navigation, hourly details, and lost rain signals.

## Changes

- Swipe left for the next day and right for the previous day.
- Remove the redundant product badge below feels-like temperature.
- Keep Now colored without a background in the 24-hour overview.
- Put Ask AI beside Weather and Radar. Give the selected navigation label the remaining width instead of squeezing it into half of the row.
- Show temperature, feels-like temperature, precipitation, probability, UV, humidity, wind, gusts, pressure, and visibility first. Missing basic values display as unavailable. Existing additional metrics are behind Advanced details.
- Keep a positive regional forecast and its precipitation components when the diagnostic median would erase them to zero. Keep regional precipitation weather codes unless an explicit phenomenon quorum replaces them.
- Highlight minority precipitation evidence without turning the model count into a probability. Wind, visibility, temperature, and UV warnings retain their priority.

## Evidence

The four new physical UI regressions failed against the preceding layout and passed after the fixes: swipe direction, the Weather label at 200% font size, basic UV/advanced disclosure, and the minority-precipitation summary. All ten UI tests passed on the Huawei Android 10 test phone.

Manual checks confirmed that the product badge is gone, the bottom controls remain aligned, and hourly UV, gusts, pressure, visibility, and rain chance appear in the basic view. Advanced details revealed dew point, wet-bulb temperature, precipitation components, cloud layers, and the remaining available metrics. No device font or viewport settings changed.

368 unit tests and 25 map tests passed. Debug/release lint and signed release APK/AAB builds passed with existing lint warnings. The unit tests cover positive regional rain with one wet contributor out of nine, trace-drizzle codes, unchanged provider probability/current values, retained components, and precipitation-only diagnostic inputs.

Independent review found two issues before release. A no-change return discarded model-spread diagnostics, and trace model disagreement could hide a strong-wind warning. Both have regression coverage and are fixed.

## Forecast limits

This is a conservative information-preservation rule, not learned local weighting. It can retain a regional forecast that later proves wrong. It does not establish improved accuracy or identify ALADIN as the best model for any particular location.

The [existing rainfall validation](research/czech-ensemble-validation.md) rejected the trained rainfall segments. No new calibrated weights are enabled. Regional model skill must be measured against independent observations and an untouched holdout; [ECMWF's verification guidance](https://confluence.ecmwf.int/pages/viewpage.action?pageId=363864334) describes probability reliability over a large sample.

The September 13 screenshot does not contain coordinates or the original full provider responses. That particular event has not been independently reproduced. A dry regional forecast plus one wet minority model therefore remains an uncertainty warning, not a claim that rain is certain.
