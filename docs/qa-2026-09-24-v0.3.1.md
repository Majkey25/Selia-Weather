# Selia Weather 0.3.1 verification

Version code 31. Checked on 24 September 2026 with the approved Huawei Android 10 test phone. Production application data and widgets were preserved.

## Radar timeline

The original range-input handler immediately replaced the pending tile layer on every crossed position. A rapid sequence discarded most of that work. The handler now waits 120 ms for the final position, cancels superseded loads, and retains the displayed image until the replacement loads.

The native WebView benchmark dispatches the same range-input events through the real page and provider layers. It counts layer creation and `tileloadstart` events. These events include cache hits; they are not a count of network downloads.

| Configuration | Layers created | Tile starts | Scrub completion, ms |
| --- | ---: | ---: | ---: |
| Original, 256 px, run 1 | 14 | 126 | 1164 |
| Original, 256 px, run 2 | 14 | 126 | 1283 |
| Original, experimental 512 px | 14 | 56 | 632 |
| Coalesced input, 256 px | 2 | 18 | 566 |
| Coalesced input, experimental 512 px | 2 | 8 | 566 |
| Final 0.3.1, 256 px | 2 | 18 | 513 |

The repeated tile-work reduction is 85.7% for this burst. The 512 px experiment did not improve completion time after coalescing and increases decoded pixels per tile. Production keeps 256 px tiles. This is a small debug-build sample, not an FPS, battery-life or universal latency guarantee. One additional run was backgrounded during capture and was excluded from timing comparison; it completed in 6028 ms with the same two layers and 18 tile starts.

Regression tests cover canceled selections, stale callbacks moving the thumb, play starting from the selected frame, mode changes, and hide/resume before and after the first frame loads. Expired forecast data still fails closed. Review caught the initial hide/resume case before release.

## Widget and page order

The old widget header divided the temperature's remaining width with another weighted column. Details now sit below the temperature. The editor uses the actual RemoteViews renderer, replacing its duplicate Compose implementation. Bitmap work runs on IO; View application runs on the main thread. Unsaved preview settings are explicit inputs and are not stored.

Four native widget tests cover compact, standard, tall and wide sizes, 160% font scale, negative temperature, independent styles, and preset Apply. English and Czech previews were inspected. These are native rendering tests in an isolated host, not acceptance of every launcher or private-image permission scenario.

Manual app verification confirmed this visible order:

1. Show all 14 days
2. View all weather details
3. Weather warnings
4. Weather history

The relocated warning action opened the real Prague ČHMÚ result with its checked timestamp and official-source link.

## Forecast limits

The operational feed now rejects an invalid model/run rainfall series as missing while retaining other usable fields. It does not invent zero rain or widen the tolerance. [Source evidence](research/2026-09-24-precipitation-and-frozen-validation.md) records the actual GRIB mismatch and retained data.

[The local/regional candidate](research/2026-09-24-local-shrinkage-candidate.md) selects weights using strictly earlier training labels. Its later audit reuses a known period at three airport stations, not a new worldwide holdout. Missing initialization provenance and runtime applicability prevent production activation. No accuracy-superiority claim or calibrated rain probability is introduced.

Google Play submission, approval and tester availability are separate from these checks. The minified release was not installed over the differently signed Play package.
