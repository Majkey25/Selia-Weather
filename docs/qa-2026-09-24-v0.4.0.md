# Selia Weather 0.4.0 verification

Version code 32. Tested on the shared Huawei Android 10 device in isolated test contexts and the separate debug application. Production app data was not modified.

## Settings and appearance

The root settings menu now has seven categories. Units and language options appear only after opening their menu. Native Back returns to the parent before dismissing settings. Notification controls preserve their existing values and Android channel links. Temperature thresholds, official warnings, wind, UV and advance notice have focused menus.

Weather colours use warm sunshine, blue cloud and darker night palettes. Ocean, Sunset and Forest ignore weather changes. Material and Minimal use solid backgrounds. App-style widgets follow the chosen appearance without changing explicit custom widget backgrounds. Tests cover unknown preferences, weather changes, opaque backgrounds and at least 4.5:1 contrast for primary and secondary text with overlapping glows.

## Navigation and gestures

Weather, Radar and Ask AI share a native pager. Left advances and right returns. The pager retains visited pages, including the existing radar WebView. Rapid button presses cancel superseded page animations. Fullscreen Back exits fullscreen before navigating away.

Radar owns map gestures. Swiping its header changes tabs. Attempts to coordinate WebView drags through asynchronous Compose state or a native intercept request failed the gesture regression. The final implementation disables the outer pager recognizer on the settled Radar page. A real Android touch sequence then changed the Leaflet map longitude without changing tabs. The same WebView survived leaving and returning to Radar.

The embedded AI page revalidates the archive on activation and app resume through the existing repository cache policy. A device test supplied a changed rainfall total after reactivation and verified that the new total appeared while the question remained. No external AI recipient was opened.

Live keyboard verification used the public Prague archive and a disposable question. With the keyboard open, navigation moved from y=2130 to y=1278, above the keyboard. Tapping Radar changed page and Android reported `mInputShown=false`. The activity uses `adjustResize` and the root applies IME padding.

## Checks

- 407 Android unit tests passed, no failures, errors or skips.
- 41 radar/location JavaScript checks passed.
- 25 final Huawei checks passed in 36.491 seconds, covering settings, history activation, page navigation, map pan, fullscreen Back, forecast layout, warnings and widgets.
- Debug lint and builds passed. Release artifacts require the separate release build and signing check.
- Independent review found and verified fixes for retained-archive freshness and secondary-text contrast. A later targeted gesture/lifecycle review found no remaining blocker.

This release does not change forecast blending, accuracy claims, warning coverage, data-sharing consent or the production calibration gates. Verification on one Android 10 phone does not prove every launcher, keyboard or device behaves identically.
